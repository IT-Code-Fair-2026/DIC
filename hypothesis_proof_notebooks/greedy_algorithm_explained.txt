================================================================================
HOW THE GREEDY MAXIMUM-COVERAGE ALGORITHM WORKS
================================================================================

Used by:
  - app/app.py, function plan_sites() (the dashboard's "Recommendations" tab)
  - hypothesis_proof_notebooks/H2_misallocation_hypothesis.ipynb, greedy_max_coverage()

Both implementations are the same algorithm. This file explains it in plain
language, then formally, then walks a small example by hand so every step can
be checked with pen and paper (or a calculator) with no code at all.


--------------------------------------------------------------------------------
1. THE PROBLEM IN PLAIN LANGUAGE
--------------------------------------------------------------------------------

We have a set of PEOPLE (grouped by SA1, each SA1 carrying a Census population
weight) and a set of CANDIDATE SITES (communities that could get a new/upgraded
tower). Each candidate site "reaches" some subset of the people, based on
whether they live within a chosen radius (5 km / 15 km / 40 km) of that site.

Given a budget of k sites, which k candidate sites reach the most people IN
TOTAL, counting each person only once even if two chosen sites both reach them?

This is the MAXIMUM COVERAGE PROBLEM, a classic, well-studied problem in
combinatorial optimisation. It is NP-hard: for any k worth asking about (we
use up to 30 in the app), there is no known way to guarantee finding the exact
best answer except checking a very large number of combinations
(n choose k, which explodes fast: even 100 candidates choose 10 is about
1.7 * 10^13 combinations). So instead of solving it exactly, we use a GREEDY
approximation with a provable quality guarantee (Section 3).


--------------------------------------------------------------------------------
2. THE ALGORITHM
--------------------------------------------------------------------------------

Inputs:
  - A universe of demand units U = {u_1, ..., u_m}, each with a population
    weight w(u_i) >= 0.  (In this project: SA1s, weighted by 2021 Census
    population.)
  - A collection of candidate sets S_1, ..., S_n, one per candidate site,
    where S_j is the subset of U that site j "reaches" (within the chosen
    radius).
  - A budget k (how many sites to choose).

Output:
  - A set of k sites T = {j_1, ..., j_k} maximising
        f(T) = w( union of S_j for j in T )
    i.e. the total weight of demand units reached by AT LEAST ONE chosen site.

Algorithm (plain English):
  1. Start with nothing chosen and nothing covered.
  2. Repeat k times:
       - For every candidate site not yet chosen, compute its MARGINAL GAIN:
         how much NEW population (not already covered by a previously chosen
         site) it would add if picked next.
       - Pick the site with the largest marginal gain. Add it to the chosen
         set. Mark everything it reaches as covered.
       - If every remaining site's marginal gain is 0, stop early (nothing
         left worth adding).
  3. Return the k (or fewer) chosen sites and the total population covered.

Pseudocode:

    covered = empty set
    chosen  = []
    for step in 1..k:
        best_site = None
        best_gain = 0
        for site in candidates not in chosen:
            new_people = reach(site) minus covered      # the NEW part only
            gain = sum of weight(u) for u in new_people
            if gain > best_gain:
                best_gain = gain
                best_site = site
        if best_site is None:
            break                                        # nothing left to gain
        chosen.append(best_site)
        covered = covered union reach(best_site)
    return chosen, weight(covered)

This is exactly what greedy_max_coverage() in H2_misallocation_hypothesis.ipynb
and plan_sites() in app/app.py do — the code is a direct, vectorised
(numpy matrix) translation of this pseudocode, nothing more exotic.


--------------------------------------------------------------------------------
3. WHY GREEDY WORKS: THE MATH
--------------------------------------------------------------------------------

3.1 Two properties of the coverage function f

    f(T) = w( union of S_j for j in T )

is:

  (a) MONOTONE: adding a site never reduces coverage.
        f(T union {j}) >= f(T)  for any T, j.

  (b) SUBMODULAR: it has DIMINISHING RETURNS. Adding a given site to a SMALLER
      already-chosen set gains at least as much new coverage as adding that
      same site to a LARGER already-chosen set:
        for A subset of B, and any site j:
          f(A union {j}) - f(A)   >=   f(B union {j}) - f(B)
      Intuition: the more territory you've already covered, the less any new
      site can possibly add on top, because more of what it reaches is
      already double-covered.

Both properties hold here because f is a simple union of fixed sets weighted
by non-negative weights — this is the textbook "coverage function", the
standard example of a monotone submodular function.

3.2 The approximation guarantee (Nemhauser, Wolsey & Fisher, 1978)

For ANY monotone submodular function, the greedy algorithm above is
guaranteed to reach at least

        f(Greedy_k)  >=  (1 - 1/e) * f(OPT_k)   ~=   0.632 * f(OPT_k)

where OPT_k is the TRUE best possible k-site choice (the one you'd only find
by checking every combination), and e ~= 2.71828 is Euler's number.

In words: greedy is never worse than about 63% of optimal, no matter how bad
the input looks — and this is a WORST-CASE guarantee. In practice, as the
worked example below shows, greedy very often finds the exact optimum, or
gets much closer than 63%.

3.3 Proof sketch (why the (1 - 1/e) bound holds)

Let OPT = {o_1, ..., o_k} be an optimal k-set, f(OPT) its value. Let
G_i be greedy's covered set after i picks, so G_0 = empty set, G_k = final
answer. Let c_{i+1} = f(G_{i+1}) - f(G_i), the marginal gain of greedy's
(i+1)-th pick.

Step 1 — By monotonicity, adding ALL of OPT on top of G_i can only help:
    f(G_i union OPT) >= f(OPT)  is false in general, but what IS true is
    f(OPT) <= f(G_i union OPT), and by submodularity applied k times (adding
    OPT's k elements one at a time to G_i), the total extra gain from adding
    all of OPT to G_i is at most k times the BEST single marginal gain any
    one of OPT's elements would offer if added to G_i right now:
        f(G_i union OPT) - f(G_i)  <=  k * max_{o in OPT} [f(G_i union {o}) - f(G_i)]

Step 2 — Since f(G_i union OPT) >= f(OPT) (monotonicity: G_i union OPT is a
superset of OPT), we get:
        f(OPT) - f(G_i)  <=  k * max_{o in OPT} [f(G_i union {o}) - f(G_i)]

Step 3 — Greedy, by definition, picks the site with the LARGEST marginal gain
among ALL candidates at step i+1 — which is at least as large as the best
marginal gain restricted to just OPT's elements. So:
        c_{i+1}  =  f(G_{i+1}) - f(G_i)  >=  max_{o in OPT} [f(G_i union {o}) - f(G_i)]
                 >=  (f(OPT) - f(G_i)) / k          [combining with Step 2]

Step 4 — Let d_i = f(OPT) - f(G_i) (the "gap" still remaining after i greedy
picks). Step 3 says d_i - d_{i+1} = c_{i+1} >= d_i / k, i.e.
        d_{i+1}  <=  d_i * (1 - 1/k)
Applying this k times from d_0 = f(OPT) - f(empty set) = f(OPT):
        d_k  <=  f(OPT) * (1 - 1/k)^k

Step 5 — (1 - 1/k)^k is a decreasing-to-a-limit sequence bounded above by
1/e for every k >= 1 (a standard calculus fact: (1-1/k)^k -> 1/e as
k -> infinity, and is below 1/e... actually approaches from below;
the clean textbook statement uses (1 - 1/k)^k <= 1/e which holds for
all positive integers k). So:
        d_k <= f(OPT) / e
        f(G_k) = f(OPT) - d_k  >=  f(OPT) - f(OPT)/e  =  f(OPT) * (1 - 1/e)

That is the result. QED (sketch). Full rigorous statement and proof:
Nemhauser, G. L., Wolsey, L. A., & Fisher, M. L. (1978). "An analysis of
approximations for maximizing submodular set functions — I." Mathematical
Programming, 14(1), 265-294.


--------------------------------------------------------------------------------
4. WORKED DEMO — SMALL ENOUGH TO CHECK BY HAND
--------------------------------------------------------------------------------

4.1 Setup

Six demand points (think: six SA1s) with populations:

        A = 100    B = 50    C = 80    D = 30    E = 60    F = 40
        total population = 100+50+80+30+60+40 = 360

Six candidate sites, each reaching a fixed subset of the demand points
(imagine these subsets came from "which SA1 centroids fall within this
site's service radius" — exactly what hav() <= radius_km computes in the
real notebook, just pre-computed here instead of from coordinates):

        Site 1  reaches {A, B}         -> population if picked alone: 100+50       = 150
        Site 2  reaches {C, D}         -> population if picked alone: 80+30        = 110
        Site 3  reaches {A, C, E}      -> population if picked alone: 100+80+60    = 240
        Site 4  reaches {B, F}         -> population if picked alone: 50+40        = 90
        Site 5  reaches {D, E, F}      -> population if picked alone: 30+60+40     = 130
        Site 6  reaches {A}            -> population if picked alone: 100          = 100

Budget: k = 2 sites.

4.2 Greedy, step by step

STEP 1 — pick the single best site.
    Site 1: 150   Site 2: 110   Site 3: 240   Site 4: 90   Site 5: 130   Site 6: 100
    Largest is Site 3 (240). PICK SITE 3.
    covered = {A, C, E}    covered population = 100 + 80 + 60 = 240

STEP 2 — pick the site with the largest MARGINAL (NEW-population-only) gain.
    Site 1 reaches {A, B}: A already covered, B is new  -> marginal = 50
    Site 2 reaches {C, D}: C already covered, D is new  -> marginal = 30
    Site 4 reaches {B, F}: both new                     -> marginal = 50 + 40 = 90
    Site 5 reaches {D, E, F}: E already covered, D and F new -> marginal = 30 + 40 = 70
    Site 6 reaches {A}: already fully covered            -> marginal = 0

    Largest marginal gain is Site 4 (90). PICK SITE 4.
    covered = {A, C, E} union {B, F} = {A, B, C, E, F}
    covered population = 100+50+80+60+40 = 330

GREEDY RESULT: sites {3, 4}, total population reached = 330 out of 360 (91.7%).
Uncovered: D (30 people, 8.3%).

4.3 Checking greedy against the TRUE optimum (brute force)

With only 6 sites and k=2, there are "6 choose 2" = 15 possible pairs — few
enough to just list every one and compute its union population directly:

    {1,2}: {A,B,C,D}         = 100+50+80+30       = 260
    {1,3}: {A,B,C,E}         = 100+50+80+60       = 290
    {1,4}: {A,B,F}           = 100+50+40          = 190
    {1,5}: {A,B,D,E,F}       = 100+50+30+60+40    = 280
    {1,6}: {A,B}             = 100+50             = 150
    {2,3}: {A,C,D,E}         = 100+80+30+60       = 270
    {2,4}: {B,C,D,F}         = 50+80+30+40        = 200
    {2,5}: {C,D,E,F}         = 80+30+60+40        = 210
    {2,6}: {A,C,D}           = 100+80+30          = 210
    {3,4}: {A,B,C,E,F}       = 100+50+80+60+40    = 330   <-- GREEDY'S ANSWER
    {3,5}: {A,C,D,E,F}       = 100+80+30+60+40    = 310
    {3,6}: {A,C,E}           = 100+80+60          = 240
    {4,5}: {B,D,E,F}         = 50+30+60+40        = 180
    {4,6}: {A,B,F}           = 100+50+40          = 190
    {5,6}: {A,D,E,F}         = 100+30+60+40       = 230

The best of all 15 pairs is {3,4} = 330 — EXACTLY what greedy found.

    f(Greedy_2) = 330
    f(OPT_2)    = 330
    ratio = f(Greedy_2) / f(OPT_2) = 330 / 330 = 1.000  (100% of optimal)

The theoretical guarantee only promises (1 - 1/e) ~= 63.2% of optimal in the
WORST case. Here greedy found the actual best answer. This is normal, not
lucky: the guarantee is a floor, not a typical outcome, and coverage problems
with real (non-adversarial) geography tend to behave much better than the
worst case, exactly as the real analysis in H2_misallocation_hypothesis.ipynb
found too — greedy came out beating essentially 100% of 10,000 random
8-site draws at k=8 on the actual NT data.

4.4 What would make greedy fail to reach the guarantee bound?

The (1-1/e) bound is tight in specially constructed adversarial examples —
e.g. one site that alone covers a large chunk of population, with the true
optimal pair instead being two DIFFERENT sites whose combined coverage is
slightly higher but each of which looks individually weak. Try, as an
exercise: build a 3-site, k=2 example where Site A alone covers 50% of the
population and nothing else, and Sites B and C together cover 100% but each
covers only ~34% alone with no single site standing out. Greedy will grab
Site A first (looks best alone), then only add one of B or C, missing the
true optimum of {B, C}. This kind of construction is how the (1-1/e) bound is
proven to be the best possible GENERAL guarantee for any greedy-style
algorithm — but as shown above, it is a worst case, not what we observed on
either the toy example or the real NT dataset.
